05 — Method

Evidence before claims.

Accuracy alone is a thin result. I try to report what changed, by how much, across how many runs, and where the method fails.

  1. M.1
    Hypothesis

    A falsifiable statement of what should change, and by how much.

  2. M.2
    Controlled setup

    One variable at a time. Fixed seeds, public checkpoints, stated compute limits.

  3. M.3
    Quantitative evaluation

    Accuracy against size and latency, with variance across runs.

  4. M.4
    Failure analysis

    Which inputs, layers or settings break, and why, not only how often.

  5. M.5
    Reproducible release

    Code, configs and logs sufficient to regenerate each table.

What a finished experiment should leave behind, as a repository layout I intend to hold my own work to:

results/
  config.yaml      # every hyperparameter
  seeds.txt        # runs reported, not best-of
  table_1.csv      # raw numbers behind each figure
  failures.md      # cases the method gets wrong
